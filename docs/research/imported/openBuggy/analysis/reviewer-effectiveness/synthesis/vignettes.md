**Last updated:** 2026-08-16

## Context

Anonymized patterns from the locked sample. Details stay in gitignored `.local/`.

## Substance

### V1 — Logic tail then CLEAN (high-iter, `scc-saves`)

Many BugBot iterations each filed a new **logic** title (races, stale UI, identity). Reviewer-a interleaved process/test lists. Last coded launches on both legs CLEAN. Supports keep-BugBot + 8-launch re-scope rather than a hard cap.

### V2 — Second high-iter identity loop (`scc-saves`)

Same shape as V1 on a sibling parent: nickname/layout logic findings, then CLEAN. `ci_skipped` heuristic fired on this parent — CI gating rec is about parent enforcement, not “the loop never helps.”

### V3 — Website-primary BugBot tail

Largest BugBot launch count in the sample; last coded BugBot CLEAN. Reviewer-a files were not UUID-linked (map gap). Do not read as “Reviewer-a was skipped on purpose.”

### V4 — Thin-dual, both legs FINDINGS (`accounts`)

One Reviewer-a + one BugBot. Variant Reviewer-a envelope (no locked opener). No in-sample CLEAN. Shows under-loop / incomplete invocation, not a successful dual-gate.

### V5 — Catalog-ish website-primary, claimed CI

Parents S10/S11: `ci_claimed_only`, both legs coded, last launches CLEAN. Loop can finish while Fast CI is only asserted in prose.

### V6 — Class mix (value vs latency)

Reviewer-a bullets cluster on process and tests; BugBot on logic. Few `BUGBOT_RULES`. Ship-set catches are **high value**; they **lengthen** the loop under fix-all, especially as test suites grow.

### V7 — Escape scanner

Almost no automated later-thread theme hits. Not a vignette of a real escape — a measurement miss.

### V8 — Security volume

Five security-class findings in 369. Rare in this sample; still BugBot’s unique class vs Reviewer-a process/tests.
