## Cline harness pointers

Thin harness. Host: Cline VS Code extension, user-level global surface at `~/.cline/` (rules + workflows).

- **Workflows** live at `~/.cline/data/workflows/` — invoke via workflow name in chat (slash-style). Companion procedure ids (`discovery`, `implementation-plan`, `plan-review`, …) map 1:1 to synced workflow files; load the matching one before non-trivial work; deep procedure via companion **Read**.
- **Bounded investigation (`repository_explorer`):** start a fresh Cline task/session for every investigation pass; never reuse the requesting conversation or a prior investigation. Begin the payload with the canonical envelope from `{{COMPANION_ROOT}}/workflow/agent-invocation.md` (`repository_explorer`; alias `none`; clean-context; read-only; `investigation`; required reading `workflow/agent-invocation.md`, `agents/repository_explorer.md`; first-read `agents/repository_explorer.md`), then pack the absolute repository path, one bounded question, thoroughness, and optional path hints after `---`. An invalid envelope returns a blocked result. A reused conversation, empty response, or routing placeholder is a routing failure — never a valid result. Return only a findings summary, key file paths, and residual unknowns; do not modify files, install, build, test, mutate git, or expand scope.
- **Dual review (serial fresh tasks):** Cline has no nested subagent spawn. Run `production_readiness_reviewer` and `bug_reviewer` as separate fresh Cline tasks, one per review leg. Begin each task payload with the canonical envelope from `{{COMPANION_ROOT}}/workflow/agent-invocation.md`; the loop parent keeps only the scoped decision/findings needed to continue and never transfers one reviewer's text to the other. Max 4 dual-review iterations per pressure-release block. Empty or instant "reviews" are routing failures — fail loud, never treat as APPROVED.
- **Gates always-on, toggle-able:** the composed always-on rule is default-enabled; the user may toggle rules in the Rules panel — do not treat a toggled-off gate as satisfied; re-enable before loop-critical steps.
- **Verification:** Rules panel (scale icon) lists discovered global rules; workflows list shows registered commands. Gate/workflow missing = discovery failure, fail loud.
- Prefer native tools over shell equivalents; git red line: read/discovery git pre-allowed, all mutating git verbs prompt — the pre-commit gate is the only sanctioned path to a local commit after dual APPROVED + Full CI; never `git push`.
